# BodyTrack · 个人训练与营养记录

为 iPhone 15 Pro 设计的简体中文、离线优先 PWA。根据用户确认，首版从 Swift 原生应用调整为网页应用：不需要 Mac、Apple 开发者年费、签名或 App Store 上架。

## 第一版包含什么

- 五个入口：首页、训练、饮食、趋势、我的；响应式布局、系统/浅色/深色主题、iPhone 安全区域适配。
- 完整的 33 个内置动作及指定的 15 天五分化循环。胸、肩、背日独立记录下巴回收与胸椎伸展。
- 前两周可选约 75% 抗阻组数；独立热身保持完整。组数按四舍五入处理，实际比例受原始组数影响。
- 每组实际次数、重量、RPE、RIR、打卡状态；单侧动作分别记录左右侧，另有动作备注和左右差异。
- 体能、疲劳、满意度、疼痛评分和部位、酸痛、肩胛与躯干控制、头颈紧张、热身感受及日记。历史实际记录与感受可修正。
- 手动输入每 100 g 营养表，六项核心营养及可选矿物质/维生素；自定义食物、常用食物库、按食材与成品重量计算的菜谱。
- 近 7/30/90 天的体重、热量、头颈紧张曲线、训练打卡和营养日均；所有图表仅使用真实录入的数据。
- JSON 计划校验、完整预览与差异、确认生效日期、历史版本启用与回滚。界面编辑动作会创建新版本，可增删、替换、修改训练量和热身模块。
- 按日期范围导出结构化 JSON、训练 CSV、饮食 CSV、Markdown 汇总报告。
- 完整 JSON 备份与原子恢复、最多 14 份设备内快照；多窗口修订冲突保护。
- Service Worker 缓存应用资源；首次准备完成后，核心记录、计算、计划文件导入、导出、备份和恢复均在本地运行。

第一版不含食物在线数据库、体态照片/视频管理和对比、通知提醒、HealthKit、扫码、OCR 或 iCloud 同步。体态部分提供体重、用户描述、颈部感受及下巴回收完成率；照片目前请保存在本地相册。没有照片诊断、Cobb 角测量或自动单侧矫正功能。

## 直接使用与 iPhone 安装

1. 在 iPhone 的 **Safari 普通浏览模式**打开部署后的 HTTPS 链接。不要使用无痕模式。
2. 本次 Sites 托管保持仅所有者可访问。首次访问可能需要使用站点所有者的 ChatGPT 账号验证托管访问权限；应用没有另建账号系统，也不会上传训练或饮食记录。若未来更换为其他静态托管，访问方式可另行调整。
3. Safari 分享 → **添加到主屏幕**；若有「作为网页 App 打开」，保持启用。之后统一从此图标进入，避免混用不同浏览器、地址或浏览模式。
4. 打开「我的 → 离线资源 → 检查」，确认资源就绪。可申请持久存储保护，但浏览器不保证授予。
5. 打开飞行模式，彻底退出后从主屏幕重新打开，验证离线打卡和刷新；这是实际 iPhone 上需要完成的验收步骤。
6. 进入「我的 → 备份 → 导出完整备份」，确认将 JSON 保存到 iPhone **文件**。建议每周备份，以及换机、清理数据、更新应用、修改域名之前备份。

首次访问和获取新版本需要联网；安装后的核心操作不依赖服务器。服务端只分发静态代码，不建立健康记录数据库。不同设备或浏览器不自动同步。域名/协议/端口变更会改变存储来源，迁移需导出后在新地址恢复。

## 本地运行（Windows、macOS、Linux）

需要 Node.js 22 或更高，无运行时依赖、无需安装包：

```sh
cd bodytrack
node scripts/serve.mjs
```

电脑打开 `http://127.0.0.1:4173`。服务默认只监听本机。`localhost` 可在电脑启用离线能力；iPhone 访问局域网的普通 HTTP 地址**不能**代替 HTTPS PWA 安装。请使用实际 HTTPS 部署验证手机。

```sh
node --test tests/*.test.mjs
node scripts/check.mjs
```

`node scripts/fixtures.mjs` 重新生成 Schema 和示例；示例 ID/时间随生成变化。无需在日常使用或部署时运行它。

## 数据结构和代码

```text
dist/
  app.mjs                 页面、表单、交互、文件交换
  core.mjs                纯领域逻辑、校验、循环、营养、导出
  store.mjs               IndexedDB、原子事务、冲突保护、快照
  sw.js                   可版本化的离线应用资源
  index.html / styles.css 原生风格中文界面
  manifest.webmanifest    安装配置
  icons/                  本地 SVG/PNG 图标
  schemas/                独立的计划、记录导出、完整备份 JSON Schema
  examples/               完整示例（记录/食品均为虚构软件测试数据）
scripts/
  serve.mjs               静态开发服务器
  check.mjs               语法、文件及 manifest 检查
  fixtures.mjs            生成可复现结构的 Schema/示例
  release.mjs             按应用资源生成离线缓存版本
  browser-check.mjs       可选 WebKit 端到端验证
tests/core.test.mjs       Node.js 内置测试运行器，无测试依赖
docs/                    Schema 与验收说明
.openai/hosting.json      当前个人 Sites 托管标识
```

所有实体使用稳定 UUID。训练会复制当时的动作目标、RIR、说明和注意事项，并为每条实际组记录分配 UUID。饮食也复制食物来源、状态和每 100 g 营养；更改食物库不会追溯修改历史。

应用资源缓存和健康数据库分别管理；更新应用资源不会清空 IndexedDB。保存时读取当前修订号、校验整个新状态，并在一个 IndexedDB 事务内写入；失败则回滚。多窗口发生修订冲突时拒绝覆盖，提示刷新。

## 周期规则

周期为胸、肩、休、背、臂、休、腿、胸、休、肩、背、休、臂、腿、休，第 16 天回到胸。

- 日历流逝不会推进。默认第一天为首次启用日，当前待完成日可手动调整。
- 只有**结束训练、确认休息完成、明确跳过**才会解决该周期位置。未完成组保留，不伪造完成。
- 延迟完成后，下一天安排不会早于实际记录日期的后一天，不会为了追赶日历跳过中间训练或休息。
- 跳过的训练保留快照，可独立补练一次；补练不再次推进周期。
- 每次启用/回滚计划建立独立的 activation ID 和新周期，旧记录保留。进行中的训练需先结束。
- 如果已安排未来生效的其他版本，再启用旧版本不会自动删除未来安排，界面会提示。应审阅版本列表的生效日期。
- 「训练完成率」采用范围内**已结束/跳过的周期训练日**为分母，排除休息、补练和未处理日；它不是日历依从率。每次训练另导出真实逐组完成率。左右侧分别计一次组记录。

## 营养正确性

`实际摄入 = 每 100 g 营养值 × 食用克数 / 100`。计算中间过程不四舍五入，仅显示时格式化。

- 名称、生熟/包装即食状态、来源必填，不内置无来源的营养数据。
- 每个核心营养字段必须存在；未知使用 `null`。空白和明确的 0 不同。
- 汇总同时给出 `value`、`unknownCount`、`complete`；全部未知的结果仍为 `null`，部分未知只显示已知小计。
- 无记录的当天合计可显示 0，但清楚注明「尚未记录」，不代表没有摄入。趋势均值不把未记录日算成 0。
- 菜谱按食材营养总量除以成品总重量换算每 100 g；任一食材该项营养未知时，菜谱该项也未知。
- 目标由用户设置，不自动推算能量需要。应用不依据宏量营养反推或杜撰标签热量。

## 备份、版本与恢复

计划 Schema、记录导出 Schema 为 `schemaVersion: "1.0"`；本地数据为 `dataVersion: 1`；食物和动作引用由备份语义校验补充检查。

- `bodytrack.records` 是按范围的分析数据，**不能恢复**；`bodytrack.backup` 才是完整恢复文件。
- 完整备份包含设置、全部计划版本与启用时间线、训练、食物库/菜谱、饮食、体重、周期日期调整；设备内回退快照不递归包含在文件内。
- 恢复前检查版本、所有实体的唯一 ID、计划引用、数值范围、组号/侧别、完成状态等。校验成功且用户确认后才写入，恢复前状态在同一事务内留快照。恢复是替换，不是合并。
- 每日首次修改前及计划启用、恢复等关键操作前，保留快照，最多 14 份，旧的滚动移除。
- 下载发起不等于文件保存完成；界面只记录发起时间。用户需要检查「文件」中是否实际保存。
- 备份为普通 JSON 文件，不是加密保险箱。请保存在你自己控制的位置。
- `migrateState` 是唯一迁移入口。首个数据版本不需要旧版本迁移；未来必须按 v1→v2→…顺序新增无损迁移及夹具测试。当前遇到未知新版本会拒绝打开/恢复，绝不静默重置数据库。

## 部署和更新

本项目是纯静态站点，可以部署 `dist/` 到支持 HTTPS、同源 Service Worker 和正确 MIME 类型的静态托管，无服务器、数据库或 API 密钥。保持稳定网址和根目录/同一子路径。`*.mjs` 必须返回 JavaScript MIME，`sw.js` 不应被登录 HTML 替换或长时间缓存。

本次使用 Sites 技能创建的站点默认保持仅所有者访问。不要通过扩大访问范围解决部署错误；从私有托管迁移到其他服务时，也先备份现有来源下的数据。

修改应用后：

```sh
node --test tests/*.test.mjs
node scripts/release.mjs
node scripts/check.mjs
```

发布时保留 `.openai/hosting.json` 的站点 ID，推送匹配源码，再打包静态资源并发布。Service Worker 使用内容散列作为新缓存版本，完整下载后等待用户在「我的」中选择更新。不要随意修改离线缓存前缀或删除健康数据库。

## 测试与验证边界

核心单元测试和真实 WebKit 引擎的本地浏览器检查已在 Windows 执行。浏览器脚本覆盖 iPhone 15 Pro 的 393×852 CSS 像素尺寸、保存后刷新、左右侧差异、食物历史快照、计划确认导入、备份在空白浏览器恢复、深色布局、离线重开和写入，以及并发事务/非法恢复保护。

可选浏览器检查需要已有的 Playwright 和对应 WebKit 浏览器（开发依赖，不属于应用运行依赖）：

```sh
node scripts/browser-check.mjs
```

可通过 `BODYTRACK_PLAYWRIGHT` 指向已安装的 Playwright 模块，`BODYTRACK_WEBKIT` 指定匹配浏览器可执行文件，`BODYTRACK_URL` 指定本地测试站点。脚本会创建虚构测试记录，只能对隔离的测试浏览器数据库运行。

**尚未在实际 iPhone/Safari、主屏幕安装容器和 iOS 文件下载/分享界面中验证。** 桌面 WebKit 与真实 iOS 不是完全相同环境；需按 [验收清单](docs/ACCEPTANCE.md) 用真机确认。PWA 不能承诺本地存储永久不被清理，也不能自动无感写入 iPhone「文件」。

关于计划与导出协议的完整说明及 ChatGPT 提示词，见 [数据协议](docs/DATA_CONTRACT.md)。
