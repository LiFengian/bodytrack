- Windows 本地 WebKit：桌面和 iPhone 15 Pro 尺寸、逐组记录后刷新、左右差异、训练结束及颈部感受、手工食品标签、历史营养隔离、计划文件预览确认、非法文件拒绝、备份下载及空白数据库恢复、深色布局、离线刷新和继续写入、并发修订与非法事务保护。
- 静态检查：JavaScript 语法、离线缓存清单文件、PNG 图标、Web App Manifest 和独立 JSON Schema 的 JSON 语法。

本地浏览器验证产物保存在被 Git 忽略的 `artifacts/`，其中含虚构测试备份，不发布、不作为真实健康数据。

1.1 另验证：默认隐藏选填的吃力程度/余力、中文说明、48 项有来源食物搜索与自动营养计算、USDA 参考份量估算标记、真实咖啡照片本机推理、确认前不入账、断网重开后再做真实推理、无照片上传或第三方请求。入口为 `node scripts/food-browser-check.mjs`。该测试不代表其他食物或复杂混合菜的识别准确率。

## 需要用户在实际 iPhone 上确认

1. Safari 打开已部署 HTTPS 链接，完成私有站点访问验证。
2. 添加到主屏幕，确认图标、独立窗口、底部导航和安全区域。
3. 输入实际次数、重量，确认键盘合适、输入不触发不必要缩放；左右侧各记录一次。
4. 强制结束应用后重新打开，确认进度保留；当日未完成前周期不前进。
5. 进入「我的」确认离线就绪，启用飞行模式，强制结束后从图标重开，完成一组和一条饮食记录，再重新打开确认数据。
6. 将完整备份保存到「文件」，查看确有 JSON 文件；恢复前预览数量和确认提示正常。可以先在另一隔离来源验证备份，避免误替换真实记录。
7. 从「文件」选择计划 JSON，先取消，确认未生效；再次导入并确认今天/未来生效，检查历史训练不变。
8. 切换深色模式，检查训练输入、弹窗、图表和菜单。
9. 验证更新：先备份，发布修改版后联网打开，待提示新版本就绪，在「我的」更新，再离线打开，历史记录应完整保留。
10. 饮食 → 拍照辅助记录：分别验证实际相机拍摄及相册选择；确认首次资源下载、照片中央裁切、错误处理和候选选择。识别后选择正确生熟条目和份量再确认，检查只有确认后才出现记录。
11. 完成首次识别后，飞行模式下关闭重开，再选照片进行第二次识别，验证实际 iPhone 的 WASM 内存及缓存可用性。用不在库里的复杂菜肴测试手动纠正，避免将候选当成测量结论。

桌面 WebKit 检查不能替代上述真机验收；iOS 的文件下载/分享界面、主屏幕存储容器、持久存储授权和私有托管登录需实际确认。
